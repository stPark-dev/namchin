# 남친렌즈 기획서

> 여자친구가 고른 인스타 사진을, 남자친구가 그대로 재현하도록 앱이 감독하는 카메라

## 전제

- 개인 프로젝트 (스토어 출시 X)
- 테스트 기기: Galaxy S23 Ultra → minSdk 34
- Android 네이티브: Kotlin + Jetpack Compose
- 서버 없음, 전부 온디바이스
- 남친 폰에만 설치. 여친은 카톡 등으로 레퍼런스를 보내고 남친이 앱으로 "공유하기"
- 인스타 API/스크래핑 사용 안 함 (약관·실효성 문제). 레퍼런스는 공유 인텐트로만 수집

## 기능 범위

| 구분 | MVP | 2차 |
|---|---|---|
| 레퍼런스 | 공유 수신 → 크롭(자동 감지, 실패 시 수동) → 골격·구도 분석 → 저장 | 투샷 레퍼런스 |
| 태그 | 온디바이스 제안 + 칩으로 수정 + 수정 데이터로 점점 정확해짐 | |
| 추천 | 현장 장면과 비슷한 레퍼런스 추천 | |
| 촬영 가이드 | 반투명 오버레이, 골격 비교, 수평계, 텍스트·화살표, 음성(남친 이어폰), 진동 | 렌즈 안내(3x/10x) |
| 매칭 | 구도 + 포즈 일치도, 좌우반전 인정 | |
| 자동 셔터 | 구도+포즈 모두 일치 0.5초 유지 시 연사. 수동 셔터 항상 가능 | |
| 야경 | 포즈 매칭·자동셔터 OFF, 구도 가이드 + 흔들림 경고 | 삼성 야간 모드(CameraX Extensions) |
| 결과 | `DCIM/남친렌즈` 저장, 레퍼런스와 나란히 비교, 베스트 컷 추천(눈 감은 컷 제외) | |

## 상세 결정

### 태그 개인화 (학습 없는 k-NN)
1. 레퍼런스 저장 시 MediaPipe Image Embedder로 임베딩 추출
2. 제안 태그 = ML Kit Image Labeling 라벨(사전 매핑) + 확정된 유사 레퍼런스들의 태그 투표
3. 남친이 칩으로 수정 → 확정 예시로 저장 → 이후 추론에 반영
4. 같은 임베딩으로 현장 프레임과 유사한 레퍼런스 추천

태그 축: 장소(카페/실내, 거리, 여행 풍경), 프레이밍(전신/상반신), 시간대(낮/야경), 계절(가을 등)

### 가이드 전달
- 음성은 남친에게만 (이어폰 전제). 포즈 지시도 남친이 듣고 여친에게 전달
- 한 번에 하나만, 반복 방지 쿨다운
- 우선순위: 수평 → 거리 → 폰 높이 → 좌우 위치 → 포즈(가장 어긋난 부위 1개)

### 자동 셔터
- 조건: 구도 일치 AND 포즈 일치, 0.5초 연속 유지
- 일정 시간 미달 시 가장 어긋난 부위를 음성 안내
- 수동 셔터 상시 제공

### 데이터 구조
- 레퍼런스는 `persons: List<PersonSpec>` 구조 (MVP는 1명, 투샷 확장 대비)

## 테스트 대상 핵심 로직 (순수 Kotlin, TDD)

- 포즈 일치도 (스케일/위치 정규화, 좌우반전 비교)
- 구도 차이 → 안내 문구 결정 규칙
- 안내 우선순위 + 반복 방지
- 자동 셔터 상태 머신 (0.5초 유지)
- 태그 추론 (k-NN + 기본 라벨 결합)
- 베스트 컷 점수
